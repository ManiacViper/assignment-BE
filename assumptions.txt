assumptions
- each service id will be unique, regardless of which client it belongs to 
- each row of the input file has service id and total amount
- service id cannot be zero
- 6 scale is good enough accuracy and half_even rounding for decimal amounts for financial transactions

simplifications
- reading the services.csv file from the app itself but in the real app
   it could have a mechanism to listen to a kafka topic for an event (which would represent the services and total amounts for a client)
- errors are being logged but we could have a dead letter queue
- will assume the columns are in the same order always in the csv file
- writes the calculated commissions to a csv file called calculated.csv to local app directory, this would be a remote storage write in the real app
