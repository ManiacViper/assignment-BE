assumptions
- each file is a representation of a client and its services
- each row of the file has client id, service id and total amount
- total amount cannot be zero
- the rate will not be a decimal amount, example 10.5%
- assuming the list will be provided to the system with a csv file
- client id should be tracked for each service commission charge as more files with different clients can be added

simplifications
- reading the csv file from the app itself but in the real app,
    it would have a mechanism to take it from a remote storage like S3 or something similar
- will assume the columns are in order always in the csv file
- logging results but in the real app we would write it somewhere in remote storage
