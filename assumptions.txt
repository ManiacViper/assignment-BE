assumptions
- each file is a representation of a client and its services
- each row of the input file has client id, service id and total amount
- total amount cannot be zero
- assuming the list will be provided to the system via a csv file and the order of the columns will be the same each time
- client id should be tracked for along with service id in case of errors to correctly identify the row that has them

simplifications
- reading the services.csv file from the app itself but in the real app,
    in the future it could have a mechanism to retrieve the input data from a remote storage like S3 or something similar
- errors are being logged but we could have a dead letter queue in the future
- will assume the columns are in order always in the csv file
- logging results but in the real app we would write it somewhere in remote storage
- writes the calculated commissions to a csv file called calculated.csv to local app directory, this would be a remote storage write in the real app
